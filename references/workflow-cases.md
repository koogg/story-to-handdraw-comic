# 流程验收案例

供维护者修改技能后手工演练，不是每次创作都要加载的指南。先只检查路由、约束和交付计划；图片质量测试需要实际生图并查看结果，不能用关键词匹配通过来代替。测试生成物放在临时工作区，真实资源导入只在临时副本中执行。

| 用户请求 | 应观察到的行为 |
|---|---|
| “提示词模式【海报】，242，主题今年中秋来常州”且没有其他上下文 | 海报分支；整理宣传对象，补问主要目的、受众、投放场景，不擅定亲子购票；不写成完整可发布稿。 |
| 提示词模式使用本地编号画风，用户将在 ChatGPT 网页附图 | 每个可复制提示词写“以该图作为艺术风格参考。”；不写本地路径、STYLE 标签、输入序号、附件角色表或上传说明。实际生图工具调用仍按工具要求传递和标记附件。 |
| “【图文海报】242，常州中秋，吸引周边年轻人来玩，手机社媒，必须有中华恐龙园，只要提示词” | 海报分支；四项简报齐全不重问；暂用3:4并说明，以城市游玩理由组织视觉与文案，不强塞票价二维码；确认后保存 poster-prompts 文件。 |
| “【单张图文】242，中秋常州，有恐龙园” | 保留单张图文路由；创作一个完整情境与互补文案，不增加营销简报、标题系统或转化入口；不强制白底小插画。 |
| “【海报】极简品牌认知，受众与线上渠道已给” | 可以极简，不强制建筑、人群或满版夜景；不因目的不是购买而要求行动按钮。 |
| “【海报】亲子活动报名，日期地点已给，报名地址未给” | 只补问真实报名入口及其他确实影响参与的缺项；可推进构思，不编造二维码、不将待补资料稿称成品。 |
| “【海报】受众和用途你来定，先做概念” | 明确列出代定的假设后推进；不重复问卷，不把假设说成用户提供的事实。 |
| “【海报】242，用附件的丰富城市空间，保留242人物画法” | STYLE与LAYOUT角色分开，最终提示词明确环境密度调整；不同时保留强制大片留白、禁止复杂建筑的冲突指令。 |
| “【海报】已确认方案，直接出提示词” | 沿用目的、受众与文案，保存完整海报提示词，不回到单张图文模板或再次确认。 |
| “267 画风，SC-016，有些事想不通就先去吃饭，仅提示词” | 社媒卡分支；一份完整提示词文件；保留 SC-016，不进入漫画指南，不生图。 |
| “267 画风，SC-016，生成一张图并附完整提示词” | 图片＋文件均交付；不被“提示词”字样降级为只交付文件。 |
| 上一轮仅提示词，本轮“按这个生成” | 沿用文案、画风和结构生图，不重新代选或再次要求授权。 |
| “画风 267，排版自动，做一张社媒卡” | 保留 267，仅匹配排版；不为三套跨风格候选更改画风。 |
| “画风自动，类型社媒卡，仅提示词，主题是放下纠结” | 至少三套不同视觉方向候选，推荐并完成文件；不因未要求生图而停在等待选项。 |
| “做一张不分镜的 IG-008 流程图，步骤 A→B→C，画风 267” | 一张含流程信息区的信息图；不套用单张图文的禁止分区规则，不增加步骤。 |
| “画风 SC-016”或“社媒卡＋IG-008” | 指出命名空间或类型冲突；不把 SC-016 当成画风 016。未解决处不擅自替换。 |
| “画风 267，六页社媒卡” | 六份独立完整提示词、六张全页卡片；同一系列保留画风，不生成一张六格漫画。 |
| “画风 217，一页六格漫画” | 一张漫画图，页内六格；主分镜机制和阅读顺序明确，页数与格数不混用。 |
| “沿用刚才那页，只把第二格错字改正” | 定点修正，保留其余内容；不触发新创作防重复；修改仍计入该图既有重试预算。 |
| “公众号正文用，只要一张” | 按已选类型生成一张；不自动额外生封面。 |
| “这些数据做信息图”，但缺少数值且要求比例图 | 不编数；能用定性关系则建议定性结构，数值不可缺时只询问必要数据。 |
| 有人物附件，要求可复制提示词，但附件没有本地路径 | 用真实附件标签及角色映射说明外部上传；不虚构本地照片路径，不声称已附到工具。 |
| 生图工具不存在，或一组三页中第二页持续失败 | 保留可用页、逐页报告状态并保存完整提示词；不把全组说成已完成，不重复生成已验收页。 |
| “给这篇文章安排插图，别改原文” | 文章规划技能，按插入位置给概念和双语提示词；不改写文章或强制变成漫画。 |
| “画风 018，主题秋天奶茶，给双语纯图提示词” | 专用风格提示词技能；不套主技能的创作性图文改编，也不导入资源。 |
| “把附件画风加入库”与“把附件中的我画进漫画” | 前者进入去重／预检／追加；后者仅作 PERSON，绝不顺手入库。 |
| “我想做长篇漫画，先聊聊设定”或给出一个示例项目 | 进入连载能力讨论但不创建目录、不把示例当正式项目；说明初始化所需的最小确认。 |
| “创建连载漫画《某项目》”，固定角色会跨回返场 | 在工作区建立独立最小项目目录和自包含档案；先做系列设定与角色基准确认，不直接把讨论稿写成定案。 |
| 新会话“继续某连载项目第六回”，并给出项目目录 | 先读项目入口、系列圣经和连续性状态，只加载本回活动角色；返场角色恢复原档案，再调用普通分镜漫画流程。 |
| 连载中角色本回临时换衣或变身 | 更新动态状态而非永久角色圣经；记录基础身份、当前形态、保留锚点和恢复条件。 |

评估时记录实际入口、交付模式、数量、沿用／变化的字段、参考附件状态及最终文件／图片状态。文档审查能发现规则冲突，但只有实际执行才可证明文件保存、附件传递和图像验收完成。
